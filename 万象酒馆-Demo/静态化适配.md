# 纯静态发布

当前游戏运行所需的提示词准备、世界书扫描、采样、TK统计、正则、预设适配、模型请求、正文与数据校验、归档和存档均在浏览器完成。发布目录不需要任何 Node API、请求代理或服务端存储。Node 只在开发、构建和隔离测试中使用。

## 构建与部署

仓库根目录运行 `npm run build`，生成 `万象酒馆-Demo/dist`；项目目录内也可运行 `npm ci` 和 `npm run build`。构建按白名单复制公开资源，不读取个人接口配置或世界书，不复制 `.runtime`、导入预设、测试、参考资料和服务端源码。内置世界书由项目规则重新生成，只合入用户明确保留的青缘、伊蒂丝、长景月汐、潘多拉四份正文。

根目录 `.github/workflows/pages.yml` 支持 main／master 推送和手动部署。GitHub 仓库 Settings → Pages 的 Source 选择 GitHub Actions；构建完成自动部署 dist。根目录的 Netlify 与 Vercel 配置也使用同一产物。游戏资源、房间、助手脚本、正则 Worker 与立绘 Worker 使用项目相对路径，可部署到 GitHub Pages 仓库子目录。

## 浏览器数据

IndexedDB 数据库 `wanxiang-tavern-static-v1` 保存活动游戏、存档槽、API配置、提示词预设、世界书、正则、脚本偏好和原始立绘。原始立绘以 Blob 保存，用仅负责本地图像的 Service Worker 提供稳定相对地址；不缓存 AI 请求或游戏版本。不能启用 Service Worker 的浏览器使用数据URL兼容导入。

初次进入此静态版本会清除旧 wanxiang 本地偏好并建立全新进度，仅运行一次；普通刷新、关闭重开和以后更新均不重复清空。青缘保留为开发者测试主角，普通模式仍需玩家创建自己的主角；伊蒂丝、长景月汐和潘多拉继续按原教程与事件加入，不预发货币、道具、角色等级或通关进度。

本地数据页提供完整备份导出／导入及持久存储申请。完整备份包含存档、世界书、导入预设、脚本偏好和立绘，默认剥离 API 密钥；切换域名、设备和浏览器时通过备份迁移。更新不覆盖用户自定义资料。

## 热更新与分包

静态构建继续输出完整的 `dist`。构建器按《发布资产划分》中的首个匹配规则为每个运行文件分组，未命中会中止构建。三个发布控制文件 `release.json`、`manifest.json`、`chunks.json` 单独管理，避免互相引用造成哈希循环。

| 文件            | v1 契约                                                                                                                              |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `manifest.json` | `schemaVersion`、包版本 `version`、`chunks: {path, bytes, sha256}` 与有序 `sources: [{id, kind, priority, baseUrl}]`                 |
| `chunks.json`   | 同版本的 `schemaVersion`、`version`、`chunks: [{id, delivery, priority, bytes, sha256, files}]` 与 `gates: {门控ID: [分包ID]}`       |
| `chunk.files`   | 按路径排序的 `{path, bytes, sha256}`。包大小为文件字节和，包哈希为 UTF-8 `JSON.stringify([[path, bytes, sha256], ...])` 的 SHA-256。 |

`initial` 描述随站点交付的首包。`background` 在游戏组装完成时加入队列，`on-demand` 由 `prefetch(ids)` 或门控加入队列。优先级数字越小越早，门控请求优先于待执行的静默包。当前房间包登记了后台预取，`after-tutorial-first-level` 保持空依赖。后续只需在 `发布资产划分.json` 的 `groups` 和 `updates` 登记文件匹配、优先级、预取方式和门控依赖。

正式发布可设置 `WANXIANG_UPDATE_GITHUB_RAW`、`WANXIANG_UPDATE_GITHUB_RELEASE`、`WANXIANG_UPDATE_GITEE`。地址均以 `/` 结尾并指向同一版本的不可变产物。Raw 和 Gitee 保留构建路径，GitHub Release 将 `chunks.json` 与各文件分别发布为 `chunks.json` 和 `asset-<sha256>`，同哈希文件可共用。镜像需允许浏览器跨域读取，续传还需要可读的 `Content-Range`。默认只使用同源产物。启用多个镜像时，以首次缓存未命中文件的 HEAD 响应延迟排序，以配置优先级处理同速或探测失败的镜像，同源产物兜底。文件请求失败、超时或校验不通过会换源，最多遍历两轮。续传使用 Range，服务器响应完整文件时从头校验。

Web 入口以同源版本清单为信任起点，校验索引的版本、大小及哈希后才排队，并使用文件的大小与 SHA-256 确认缓存和新下载内容。已验证字节以路径和哈希为键复用，半包单独保存。Cache 存储适配器可在页面或 Service Worker 中用，现有 Service Worker 仍负责本地立绘。未来文件系统适配器实现异步 `read(area, file)`、`write(area, file, blob)`、`remove(area, file)` 即可，写入应原子替换单条记录。场景资源仓库按当前资产目录的内容哈希复用已校验字节，新页面或原生端可对候选清单调用 `checkForUpdate` 获取差异。Web 首包随正常页面发布生效，正式重复发布时应更新版本。

初次通关后的再次出发入口调用 `requestGate()`。需要等待时，界面可用 `queryGate()`、`subscribe(listener)` 读取 `state`、`loadedBytes`、`verifiedBytes`、`totalBytes`、各包状态和错误，并在重试时调用 `retryGate()`。切源重下可使接收进度回落，放行以全部依赖校验且落盘为准。未来界面可在收到 ready 后重试原出发操作。

## AI连接与兼容

所有API均为浏览器直连，服务商需要允许当前网页跨域访问。“在此设备记住密钥”默认勾选，保存后写入该浏览器数据库，代码更新和正常重启后保留。主动取消后只在本页内存中保存，按钮和提示明确标记“仅本次使用”；可点击“长期保存此连接”恢复。API配置采用严格落盘事务，写入失败会回滚并明确提示，不能显示为已保存。连接配置和密钥不进入发布包；默认备份剥离密钥但保留保存偏好。图床若不支持跨域读取，可通过本地图片文件导入。

两端共用 src/ai/pipeline 的纯模块，原开发服务只保留测试适配器。保留 Advice、Kemini工具正文、Reborn消息重组与流式预处理的现有语义，不执行未审阅的输出处理脚本。正则在可终止的模块 Worker 中运行，仍有1500ms超时。o200k分词表和依赖随发布包自带，无CDN依赖。

生成总超时180秒，取消不自动重试，刷新后中断请求并保留已保存的玩家消息。只有成功接受生成才提交世界书计时状态。预览、错误及本地重校验不额外调用上游。

## 离线与读档

关闭页面、刷新或重新加载存档后回到酒馆大厅，不续接未完成战斗。未完成副本的剧本、旅途记录及其临时归档来源一并清理；已完成副本、角色、已经取得的资源、聊天和配置保留。旧版本战斗检查点只用于识别并清理未完成剧本，不再恢复战斗。

## 验证

集中入口 `node tools/test.mjs --scope quality,core,static,server,settings,chat,onboarding,expedition`。static组单独使用仅提供文件的HTTP站点，在仓库子路径加载发布包，任何 /api/ 请求都会失败并记录；验证六种请求、JSON与SSE、正则、TK、预设脚本、立绘、备份剥离密钥、刷新后的记录／配置和战斗检查点。其他组使用隔离的开发适配器回归原游戏流程，均不调用真实用户接口。
