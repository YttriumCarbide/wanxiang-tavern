# 纯静态发布

当前游戏运行所需的提示词准备、世界书扫描、采样、TK统计、正则、预设适配、模型请求、正文与数据校验、归档和存档均在浏览器完成。发布目录不需要任何 Node API、请求代理或服务端存储。Node 只在开发、构建和隔离测试中使用。

## 构建与部署

仓库根目录运行 `npm run build`，生成 `万象酒馆-Demo/dist`；项目目录内也可运行 `npm ci` 和 `npm run build`。构建按白名单复制公开资源，不读取个人接口配置或世界书，不复制 `.runtime`、导入预设、测试、参考资料和服务端源码。内置世界书由项目规则重新生成，只合入用户明确保留的青缘、伊蒂丝、长景月汐、潘多拉四份正文。

根目录 `.github/workflows/pages.yml` 支持 main／master 推送和手动部署。GitHub 仓库 Settings → Pages 的 Source 选择 GitHub Actions；构建完成自动部署 dist。根目录的 Netlify 与 Vercel 配置也使用同一产物。游戏资源、房间、助手脚本、正则 Worker 与立绘 Worker 使用项目相对路径，可部署到 GitHub Pages 仓库子目录。

## 浏览器数据

IndexedDB 数据库 `wanxiang-tavern-static-v1` 保存活动游戏、存档槽、API配置、提示词预设、世界书、正则、脚本偏好和原始立绘。原始立绘以 Blob 保存，用仅负责本地图像的 Service Worker 提供稳定相对地址；不缓存 AI 请求或游戏版本。不能启用 Service Worker 的浏览器使用数据URL兼容导入。

初次进入此静态版本会清除旧 wanxiang 本地偏好并建立全新进度，仅运行一次；普通刷新、关闭重开和以后更新均不重复清空。青缘保留为开发者测试主角，普通模式仍需玩家创建自己的主角；伊蒂丝、长景月汐和潘多拉继续按原教程与事件加入，不预发货币、道具、角色等级或通关进度。

本地数据页提供完整备份导出／导入及持久存储申请。完整备份包含存档、世界书、导入预设、脚本偏好和立绘，默认剥离 API 密钥；切换域名、设备和浏览器时通过备份迁移。更新不覆盖用户自定义资料。

## AI连接与兼容

六种API均为浏览器直连，服务商需要允许当前网页跨域访问。密钥默认仅在本页内存；玩家主动勾选“在此设备记住密钥”后才保存到该浏览器数据库。连接配置和密钥不进入发布包及默认备份。图床若不支持跨域读取，可通过本地图片文件导入。

两端共用 src/ai/pipeline 的纯模块，原开发服务只保留测试适配器。保留 Advice、Kemini工具正文、Reborn消息重组与流式预处理的现有语义，不执行未审阅的输出处理脚本。正则在可终止的模块 Worker 中运行，仍有1500ms超时。o200k分词表和依赖随发布包自带，无CDN依赖。

生成总超时180秒，取消不自动重试，刷新后中断请求并保留已保存的玩家消息。只有成功接受生成才提交世界书计时状态。预览、错误及本地重校验不额外调用上游。

## 战斗恢复

战斗保存可操作回合的完整检查点，包括当时的角色库、背包、战斗状态、阵容、行动计划、地图进度、手记与临时闲聊。刷新恢复最近一个可操作回合，不恢复一半播放的动画；结算页面刷新可能回到该战最后的可操作检查点。检查点的角色库和战斗同步恢复，防止重复领取经验、金币或物资。进入下一场或返回酒馆后保存新的边界。

## 验证

集中入口 `node tools/test.mjs --scope quality,core,static,server,settings,chat,onboarding,expedition`。static组单独使用仅提供文件的HTTP站点，在仓库子路径加载发布包，任何 /api/ 请求都会失败并记录；验证六种请求、JSON与SSE、正则、TK、预设脚本、立绘、备份剥离密钥、刷新后的记录／配置和战斗检查点。其他组使用隔离的开发适配器回归原游戏流程，均不调用真实用户接口。
