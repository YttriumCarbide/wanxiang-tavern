# 装备、造物与同行者事件

每名角色有三个装备槽。一件实体装备只能由一人佩戴；同款可以构造多件。整备中修改装备自动保存，基础属性与成长相加后编译进战斗快照，副本途中不能替换装备。基础行动次数合计最多6次，敏捷额外加成仍最多2次，所有行动照常消耗AP。每趟开始重置触发次数，营火与下一场战斗保留次数，预演不消耗真实次数。

## 统一的被动与装备规则

装备和新被动共用 `rules`。旧位置被动与后援治疗也通过同一个求值器执行；旧整备法力加成继续作为战斗外基础数据处理。

| 部分     | 支持内容                                                                                                                                                        |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 生效模式 | 持续光环；满足条件时响应事件                                                                                                                                    |
| 事件     | 每场战斗开始、正常回合开始/结束、进入前场/后场、进攻前/后、释放主动技能、造成/受到生命伤害、击杀、获得治疗、消耗/恢复法力、玩家使用道具、获得正面/负面/任意状态 |
| 条件     | 前场、后场、有正面/负面/任意状态、无状态、有护盾、生命/法力百分比高于或低于阈值、至少第几回合、某个状态达到指定层数                                             |
| 目标     | 自己、本次目标、攻击来源、全体/前场/后场队友、生命比例最低队友、全部敌人、生命最低敌人                                                                          |
| 事件效果 | 伤害、治疗、恢复法力、护盾、施加状态、净化指定状态                                                                                                              |
| 持续光环 | 力量、守势、铁皮、再生、敏捷；条件失效立即消失，不往真实状态重复叠层                                                                                            |
| 次数     | 每条事件规则每趟副本1～50次；持续效果不限次数                                                                                                                   |
| 基础加成 | 生命、法力、普攻、技能伤害、行动次数、技能耗蓝降低                                                                                                              |

同条规则的条件全部满足才生效，最多六项。条件读取当前真实状态，不递归读取其他光环。治疗和法力不超过上限，不复活濒死单位。攻击事件包含普攻与伤害型主动技能，释放技能事件排除普攻。受到伤害要求直接生命伤害实际生效，完全被盾吸收不算；中毒、流血独立结算，不派发攻击或直接伤害事件。道具使用事件由玩家整队使用道具触发，各角色分别检查自己的规则。

装备和被动产生的伤害、治疗、法力和状态不再次派发触发事件，尤其不触发“获得正面/负面/任意状态”，防止反击、治疗或状态循环。新规则不能增加AP、复活、执行脚本或修改数值协议。技能和装备触发伤害仍进入同一个引擎与真实播放事件。

## 以太凝聚器

走廊尽头右侧装置可打开凝聚器。先将已归档且无待处理冲突的物品批量细化为装备目录，再按原物品以太价值购买实体装备。普通消耗品仍由左侧售货机使用金币购买。

造物API拥有独立连接，使用内置提示词，不加载社区预设、角色设定或公共世界书。请求只包含造物规则、尚未细化物品、来源地图及各自的对应副本正文，同一剧本只发送一份，用索引关联物品。相同地图、名称、描述及价值的已细化物品复用已有目录，不反复生成；同名新设定可另行凝聚。多个来源按上下文和输出容量分批，每批一起细化；全部成功才提交，失败或取消不保存部分结果，不扣以太。单次请求超时三分钟。

强度预算为 `min(80, max(1, floor(sqrt(原以太价值) × 1.5)))`。基础属性费用：生命每点0.5、法力1、普攻/技能伤害3、行动次数24、耗蓝降低10。事件效果费用为数值之和，状态每层5、净化每种3；群体目标乘3；持续光环再乘3，事件乘 `max(1, 每趟次数/3)`。总费用向上取整，超预算直接拒收，售价始终由代码取来源价值。此预算是当前可调整的统一强度规则，不接受模型自报预算或价格。

## NPC召唤与一次性对话

印记召唤可选择已知NPC，使用角色API细化原有身份与经历；混沌召唤按官设、已知NPC、全新创作各三分之一决定来源，空池明确提示，不改概率、不扣契约。潘多拉不在抽取范围。

NPC成功通过角色协议校验并保存后，才扣一份契约并移出NPC归档；保留原副本历史。已细化姓名不会再次归档为可召唤NPC。失败、取消、改名返回均保留原归档和契约。

角色响应可以在根节点附 `arrivalDialogue`，2～5项 `{speaker:"character"或"player",text:"对白"}`。协议要求新召唤生成这段对话；旧响应与官设使用简短初见对话补充。对话框使用双方立绘或默认立绘，只展示一次，不写入角色设定、聊天记录或长期记忆。

## 整备、潘多拉和开发者选项

生成新剧本时显示整备页，冻结出发成员，只能交换位置、调整装备、查看背包或取消生成；新站位和装备用于实际出发。普通酒馆整备也能管理装备和查看背包。

第三次不同的完整副本结算后返回酒馆，播放潘多拉在门口醒来的居中文本与她、长景月汐、伊蒂丝的对话，不生成主角台词。结束后加入角色池，并在有空位时加入出发阵容。旧档已拥有潘多拉则不重复演出。下一趟教学前后场交换，要求实际结算一次后场换入，预演或取消不能完成教学。

顶部“总结”位于“归档”左侧。游戏设置中的“开发者模式”显示主角生成、剧本生成、中途返回和调整设定开关。现有生成偏好保留；关闭开发者模式不会改写这两项偏好。中途返回和归档编辑必须同时开启开发者模式及各自开关，普通模式隐藏对应按钮，并在控制器拒绝绕过按钮的操作。失败或完整结算允许返回，普通战获胜的营火不能跳过后续战斗。
