# 开发规范

## 开发环境

Web项目使用原生ES模块、Three.js和Node静态服务，Node版本要求22.13以上，建议使用`.nvmrc`对应的22系列。运行游戏仍可直接双击上级`一键启动.cmd`，不需要构建或安装前端运行依赖。

开发时在本目录执行 `npm ci`，恢复已提交的精确依赖锁。`npm run lint`检查JavaScript，`npm run format`统一排版，`npm run check`集中检查质量与核心规则。编辑器设置在上级`.vscode/`，支持保存格式化、ESLint诊断和Edge断点调试。

Python建模工具使用上级`建模工具/.venv`，依赖锁在`requirements-dev.txt`。新机器在该目录执行 `python -m venv .venv` 和 `.venv\Scripts\python -m pip install -r requirements-dev.txt`。日常玩法和UI开发不重新生成模型。

## 结构与边界

模块职责以`架构.md`为准。应用状态只有`app/session.js`一个所有者；控制器在`app/application.js`组装，不新增顶层可变变量或循环导入。新面板、输入方式和规则分别落入对应模块，避免重新建立巨型应用文件。

- 引擎不依赖DOM、Three.js和动画时间；规则预演与实际播放共用同一份事件。
- 行动类型为`skill/swap/reposition/item`，结算事件为`hero/enemy/swap/item`等，不能混用。回合归属统一通过`turn-flow.js`。
- 配置在启动前集中校验；行动的ID、类型、技能、AP、时间格和目标方向在进入模拟前校验，非法内容返回`invalid`。蓝量、濒死、时点阵型等动态条件在实际模拟位置检查。
- 新增数据必须有稳定ID，不用中文显示文案作为逻辑分支。用户确认的玩法规则仍以设计对照和交互文档为准。
- 全局监听器用`createEventScope`注册并销毁；Three.js资源用`createResourceScope`管理，包括替换的材质和异步晚到的资源。卸载后的异步任务不得继续渲染。
- 页面执行代码放在模块中，样式放在组件文件中。只修改对应组件的样式，响应式规则也归该组件，不建立新一轮覆盖补丁文件。
- 模板可用`html`标记方便格式化；该标记不自动进行安全转义，用户文本进入HTML前必须调用`escapeText`。

## 格式与依赖

JavaScript用UTF-8、LF、两空格，保留分号，由Prettier统一排版；不手写压缩代码。ESLint检查无用变量、未定义名称和领域层依赖边界。质量组还检查循环导入、CSS语法／属性／重复声明、HTML外部引用和依赖锁。

Python使用Black、四空格、100列约定，依赖独立虚拟环境。CMD内容只用ASCII命令和CRLF，中文文件名可保留；PowerShell用UTF-8 BOM，启动实现只有`launch.ps1`一份。后台进程隐藏启动，关闭前核验服务身份。

新增npm包必须精确锁定直接依赖并更新`package-lock.json`；浏览器测试从项目依赖加载Playwright，不依赖开发者私有路径。第三方Three.js保留在`vendor/`及其许可证中，不纳入自有代码格式化。

## 集中测试，改哪里测哪里

所有测试从`node tools/test.mjs`进入，一次提交本轮需要的组，收集完所有失败再修。产物统一写入`.runtime/tests/`，禁止重新建立临时QA脚本。

| 改动                         | 一次性命令                                                    |
| ---------------------------- | ------------------------------------------------------------- |
| 文档、格式、引用             | `npm test -- --scope quality`                                 |
| 数据、规则、配置契约         | `npm test -- --scope quality,core`                            |
| 界面、输入、动画、样式       | `npm test -- --scope quality,ui`                              |
| 服务                         | `npm test -- --scope quality,server`                          |
| 启动和关闭                   | `npm test -- --scope quality,launcher`                        |
| 建模脚本格式与语法           | `npm test -- --scope models`                                  |
| 按文件合并范围               | `npm test -- --changed src/app/selection.js,styles/cards.css` |
| 只重跑失败组                 | `npm test -- --failed`                                        |
| 只复核样式布局               | `npm test -- --scope layout`                                  |
| 涉及副本推进／继承的完整验收 | `npm test -- --scope core,expedition`                         |

`npm test`默认只执行快速核心逻辑。UI和布局共用一次浏览器会话；布局基准覆盖普通桌面、大屏、平板、手机横屏四类实际断点。`--scope all`是重大重构或明确完整验收使用，不能用于每次小修改。普通文案和边距修改不跑五场副本。

布局基准由`npm run test:baseline`显式更新，失败时不能自动重录来掩盖问题。基准按平台保存，其他平台仍运行交互用例。浏览器默认用本机Edge，可用`TEST_BROWSER`指定通道；新机器需要提供对应浏览器。

失败后只修复并重跑失败或受新修复影响的组，可以用 `--failed --scope quality` 合并额外影响范围，报告保留其他通过结果；已通过且未再改动的组不反复运行。新用例必须验证行为，不复制实现，不为可逆的小改动扩展成大规模回归。

## 交付

死亡美术单独微调时使用 `node tools/test.mjs --scope quality,death-effects`，只复核真实引擎驱动的体素消散、淡出、Boss镜头、选中扫光循环与资源释放，不重复跑已通过的完整UI或副本。`ui`仍包含同一组检查；同时选用两个范围时复用检查结果。音乐资源与场景分配使用 `--scope quality,core,audio`，验证真实浏览器解码、地图／Boss选曲与淡入淡出释放。

说明最终行为、实际测试命令和结果。`.runtime`、`node_modules`、`.venv`与生成压缩包不入库；原始VOX、源GLB、唯一建模脚本和锁文件要保留。删除旧文件默认放回收站并留记录，用户要求导出时才打包。不要更换框架、加入服务或改变数值来顺带解决整理问题。

## AI生成改动

接口与正文／数据附录契约遵守[API接入.md](API接入.md)。发布版本只使用浏览器直连。密钥默认只在本页内存，用户主动勾选“在此设备记住密钥”才写入本机浏览器数据库；默认备份与发布包始终剥离密钥。开发服务仅供隔离测试使用。模型输出必须走白名单校验，模型输出禁止eval、动态脚本、任意资源URL和修改全局官方角色。用户主动导入的预设助手脚本按1.3扩展宿主规范在独立沙箱运行。每趟副本固定角色身份和技能结构，升级仅在下一战边界应用代码生成的数值成长，剧情只记录实际播放过的历史。

角色生成、剧本演出或AI兼容协议改动，按实际受影响范围合并验证。纯提示词条目拆分、迁移和注入排序运行`npm test -- --scope quality,core,server`，涉及界面则合并ui；核心用例应覆盖两种API的真实请求拼装和返回校验。`ai`组使用本地模拟上游并重放五场真实浏览器战斗，仅在副本推进、资源继承、Boss规则变化或用户明确要求时运行；普通UI和提示词整理不跑该长组，不读取真实用户的接口密钥。

角色API使用schemaVersion3双层JSON，设定集1000～1500tokens、经历150～260字及召唤过程是提示词的创作目标，不能用正文关键词、固定措辞、文风或总字数拒收格式正确的角色。只校验JSON/标签、字段结构、类型、技术容量和游戏所需的ID、关联与数值范围。不可拿整个响应usage或JSON长度代替正文统计。数据校验编译后不持久化原始响应，设定去掉JSON外壳只保存文字；姓名、职业、普攻、两个技能名称仅在setting生成一次；data不重复填写，编译时按同序技能槽位继承。旧v3响应中的重复名称兼容读取，以setting为准，不进行跨层同名拒收。剧本v3分为story五段自由小说正文与data元数据。前四段对应四场普通战斗，第五段在Boss获胜后展示；不强制拆说话人、动作、对白，不硬性指定文风、描写比例、任务式开场或篇幅。数据层沿用title/synopsis/setting/tags/npcs/nextHook及原有范围。只校验格式、技术容量和数据层合法性；v1/v2仍兼容，历史只记录实际展示的正文与代码确认的战斗事实。

分层提示词采用`prompts/prompt_order`协议，输出格式通过世界书的SYSTEM @D0条目发送，默认顺序9999。完整Assistant示例保留为可校验的编辑参考，默认停用，不把某个官方角色或固定故事常驻发送成已完成回答；用户主动启用的示例可发送，上游原样回传示例可记为output.source参考信息，不能当成格式错误拒收，不自动重试；预览不能触发上游模型请求。API连接预设与提示词预设分开持久化，严禁把密钥带入提示词导出。测试通过`AI_PROMPTS_DIR`使用独立预设目录，不能改实际用户的预设文件。

生成诊断分别在session.ai.diagnostics.character和script保留各自最新原文、校验文本、错误路径和修复记录，刷新即清除，不进入世界书／AI上下文。上游最终JSON必须在唯一一组wanxiang_json标签中；先提取标签，再运行AI返回正则与校验，禁止扫描标签外JSON作为回退。标签生成不发送冲突的response_format，本地始终严格校验；手动本地重校验接收右侧提取出的JSON。格式修复必须在字符串外处理，禁止猜缺失内容、改数值或跳过完整校验。本地重校验不得调用上游；失败结果不能进入角色池或副本。

世界书导入须保留未知extensions并校验已知字段，不执行脚本。预览与实际发送必须走同一generationRequest，禁止另拼一份预览；TK必须统计最终全部messages并标明参考分词器和估算开销，不能冒充服务商usage。世界书计时状态只在成功接受生成后提交，预览与失败不推进。表单自动保存归控制器生命周期管理；AI_WORLDINFO_DIR必须与测试配置一起隔离。

社区预设适配以[社区预设使用.md](社区预设使用.md)为准。创作要求存单一世界书，API发送对象在条目扫描前过滤；输出格式条目使用SYSTEM @D0与顺序9999，代码保留读取校验。正则使用独立worker与超时，区分发送前、原始返回与仅显示，显示替换不回写原始设定。新增兼容宏须验证真实变量语义，用户选用预设时允许执行其附带的酒馆助手脚本，但只能在 preset-extensions 管理的隔离 iframe 内运行；通过白名单桥接修改该预设的开关和变量，不得接触密钥、主页面或战斗状态。MVU和模板引擎未提供自动兼容。

1.2探索路线以exploration.js与content/regions.js为准，每个地点仍是一整趟五场副本。节点种子同时决定发送给AI和真正战斗的名单；环境规则在newEncounter写入纯状态，禁止界面自行计算。只有第五场胜利才能推进该地图、提交伏笔和产生后继；中途退出、失败、预览与重复回调都不得推进。地图路线历史独立保存，不随总探索次数提高怪物基础属性。改动推进时通过统一expedition组验证完整五场及接续；其余已通过范围不重复跑。

主角开局与教程涉及队伍人数和副本推进，统一合并core、ui、onboarding与expedition范围；onboarding使用隔离上游完成真实五场教学流程。旧六人存档界面测试通过legacySession显式装载兼容存档，不绕过生产开局检查。

当前版本移除奥义和觉醒任务。协议只生成普攻与两个技能，旧存档及旧返回的退役字段只兼容剥离，不进入战斗定义。立绘按角色池唯一ID保存，禁止按模板或站位写入；按原比例顶部对齐，留白补纹饰。逐字计时器归dialogue控制器，关闭及销毁时清理。

敌人意图展示的定向验证使用 `node tools/test.mjs --scope quality,intents`，覆盖三敌人同时预演、事件伤害、状态图标、单体／取消、横屏及DOM复用；ui组包含同一检查，同时选择两个范围时复用结果。

聊天与脚本宿主的定向浏览器检查使用 `node tools/test.mjs --scope quality,core,chat`。ui组包含同一检查；剧本改写只替换未经历正文，禁止更改引擎状态、已显示历史或当场章节。

主题战场、天气、走廊与房间交流的定向检查使用 `node tools/test.mjs --scope quality,core,models,environment`。environment共用一个浏览器，检查八张主题资产、各类天气与场地接触、三门入口视角、两间客房和主卧的移动及共享聊天。与ui同时选择时复用已完成的环境检查，不重复加载图册和房间。不涉及副本推进，无需运行完整五战。

仅修改房间进出位置、门口交互或交流按钮布局时使用 `node tools/test.mjs --scope quality,rooms`，只检查房间导航和共享交流，不加载地图图册。environment包含同一检查，同时选用时复用结果。

仅修改战场模型／外围环境时使用 `node tools/test.mjs --scope quality,core,models,artbook`。artbook核对新旧地图卡牌屏幕位置和大小，等待入场动画结束后截图；core比对原始地面缓冲区并验证新增装饰未侵入中央战斗区，不重复运行房间导航。

接口设置与第三方预设的定向验证使用 `node tools/test.mjs --scope quality,core,settings`。设置 WANXIANG_TEST_PRESET_FILE 可使用实际用户预设验证导入、消息预览与脚本开关回写；测试仍使用隔离配置，不读取或调用用户的真实接口密钥。

## 2026-10-18 教程与旅途记录扩展

剧本输出使用v4：根节点schemaVersion/story/data，data仅title/tags/npcs/items/nextHook；nextHook只保留setting。tags为关键词；NPC不能是队伍成员，appearance和history各至少25字，encounter为首次出现的0～4场索引。道具description最多20字，value为以太价值，encounter为实际收集场次。旧v1/v2/v3存档继续读取。archives.js仅归档实际展示过的里程碑，同名NPC合并来源；完整通关才将物资折算为以太，并用runId防止重复结算。重置剧本更新同一份剧本，冻结已经历正文及已归档数据。

酒馆正文统一用wanxiang_chat标签；交流指令独立置于wanxiang_actions标签中的JSON，含affection数组（id/delta，0～5）和agreeToAdventure角色ID数组。正文与指令分开校验和展示。relationships.js只允许队友每次下副本之间前三次正向好感增长，下副本重置次数；不修改战斗数据。所有酒馆地点与角色共用tavernChat，system/divider只表示场景切换，允许逐条删除。

教程通过实际预演与结算事件验证要求；通关后依次完成以太说明、召唤、圆桌完成一次交流及再次出发。每场战斗前自动打开手记（教程第一场手动教学除外），最终战获胜先展示结尾，关闭后才结算。地图按数字顺序解锁，各地保留独立的曲折路线。

## 装备与造物规则

装备和被动统一使用triggers.js的规则白名单，经engine.js唯一模拟结算。条件、目标、次数和基础加成不得在界面重新计算；每趟触发次数跨战斗继承。触发产生的效果禁止递归触发，击杀必须由原始伤害确认，不能把触发追加伤害造成的死亡记成原攻击击杀。造物API使用独立连接与内置提示词，源物品售价和预算由代码绑定，批量成功后才接收；已知NPC成功细化并保存才移出归档。召唤初见对话仅临时展示。

整备生成期间冻结成员身份，可调整站位与装备；副本中不得更换装备。开发者的中途返回和归档编辑同时要求总开关及分项开关，隐藏按钮不能替代控制器检查。新增定向浏览器检查合并到settings范围，包含凝聚、构造、装备、NPC、生成中整备、潘多拉事件与真实交换。

## 纯静态版本

发布入口为bootstrap.js，平台存储与请求由组装入口注入；大型资料使用IndexedDB，不将聊天正文或图片字节写入localStorage。API规则、预设处理和解析统一维护src/ai/pipeline，server中只保留Node测试适配器，不另写第二份规则。公开发布目录由tools/build-static.mjs白名单生成，任何个人资料不得作为构建输入。内置世界书只从项目协议和已批准四位角色正文构造。定向验证增加static范围，必须使用无API服务的文件站点并覆盖仓库子目录；具体见静态化适配.md。
