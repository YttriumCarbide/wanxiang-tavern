# 社区预设、正则与世界书

设置 → 提示词预设 → 导入酒馆预设JSON → 选择当前接口使用此预设。首次安装列表为空，需要自行导入。预设可供角色与剧本两个API共用，各自选择；连接地址、密钥与最大输出仍在接口设置，提示词预设不导入认证信息。支持最多8MB的预设文件、1000条消息和100万字提示词正文。SYSTEM、USER、ASSISTANT与prompt_order保留，列表拖拽排序，点名称或铅笔弹窗编辑。temperature、top_p、frequency_penalty、presence_penalty在有效范围内随预设发送，预览列出实际参数。

设置 → 接口设置：先选择角色API或剧本API用途，填写URL、模型、Key，再命名并保存预设。两个用途共用同一份API连接预设列表，选择后立即填入配置；这份列表和文风提示词预设相互独立。密钥由本机服务保管，不在表单回显。

设置 → 世界书：使用一本“万象酒馆世界书”。旧公共设定、怪物图鉴及其他原有条目首次合并，保留来源与原文件，不重复迁移覆盖修改。导入其他世界书会追加条目并重新分配UID。每条有两个独立的“发送给”勾选：角色API、剧本API，都不勾选则不发送。勾选仅决定接收对象，仍需满足开关、蓝绿灯、关键词、递归、概率和预算条件。界面暂不提供世界书导出，导入及保存仍保留扩展字段。

## 注入位置与身份

条目采用酒馆式行布局，折叠时直接编辑开关、名字、蓝灯常驻／绿灯关键词、插入位置、深度、顺序和概率。点左侧箭头展开主要关键字、可选过滤器及其逻辑、扫描深度、大小写、完整词、递归选项、发送对象与正文。关键词用逗号分隔，正则内部的逗号保留；内容旁显示参考TK与UID。未展示的导入字段仍原样保存。顶部“角色格式 · @D”“剧本格式 · @D”直接定位实际约束JSON输出的条目。

- 角色定义之前 / 之后：围绕预设中的worldInfoBefore、charDescription、worldInfoAfter插入，适合世界观、人物背景等资料；预设缺少世界书占位时按实际角色描述块回退。
- 插入深度 @D：深度0在当前消息尾部，1在倒数一条前，以此类推；SYSTEM / USER / ASSISTANT分别产生对应身份的消息。深度和身份控件仅在此位置生效。
- 作者注释前后、示例消息前后、Outlet按各自锚点插入。Outlet需在预设引用{{outlet::名称}}。

生成要求已移到世界书的“角色生成·设定与数据要求”“副本剧本·自由叙事与伏笔”及格式示例条目，可修改位置、身份、对象和内容。通用预设不再写死文风。JSON Schema通过独立的“JSON输出格式 @D”SYSTEM条目注入（深度0、顺序9999），可在最终预览看到动态展开结果；代码负责校验返回：角色v3双层、剧本v3的五段文本和独立数据层、合法ID与游戏数值范围仍受校验；正文关键词、文风及总字数不作为拒收条件，不可通过世界书绕过。

## 正则

设置 → 正则：来源可选全局或任一预设内嵌正则，导入、编辑、启停、排序、导出与测试均可用。执行顺序为全局在前、当前预设内嵌在后。支持findRegex、replaceString、捕获组/$0/{{match}}、trimStrings、placement、markdownOnly、promptOnly、runOnEdit、深度及substituteRegex。

用户输入、发送前消息、世界书正文和AI返回使用对应位置；AI返回正则只处理wanxiang_json标签内部，标签外文字不会交给正则或游戏数据解析；仅显示规则只生成显示副本，不改变人物原文、战斗数值或历史上下文。替换生成的HTML按文字显示，不执行脚本。正则在有时限的独立worker中处理，超时返回明确错误，服务器继续响应。生成诊断保留上游原文与替换记录，最终发送预览统计处理后的消息TK。

## 当前兼容范围

常用宏支持char/user、人物与场景、lastUserMessage、setvar/getvar/addvar、incvar/decvar、对应globalvar名称、trim、注释、random/pick和Outlet。变量仅作用于本次请求，不实现跨会话全局存储。addvar支持文字拼接、数字相加、数组追加；预览与发送不会提交游戏状态或调用模型。

酒馆助手、MVU、模板脚本、外部记忆插件、向量检索和斜杠命令不执行，保留扩展数据并提示未适配，不能把其悬浮窗或脚本渲染视为已兼容。未知宏给出具体名称，不悄悄发送占位符。社区预设产生的其他文字可放在最终结果标签外，代码只读取唯一一组`<wanxiang_json>...</wanxiang_json>`内的完整JSON。预设若仍强制其他最终格式，请关闭冲突层或调整要求；以最终发送预览与生成诊断为准，不要求输出思考过程。

原版布局与字段对照来自用户提供的SillyTavern源码：public/index.html的World Info条目、public/scripts/PromptManager.js以及public/scripts/extensions/regex。这里复现编辑与数据流程，不启动或修改用户的SillyTavern实例。

版本5默认停用两份内置完整格式示例，保留为编辑参考，避免格雷档案或固定故事污染实际生成。默认格式约束继续来自SYSTEM @D0动态Schema。自定义示例与社区预设不被停用；上游原样返回本次发送的完整ASSISTANT示例时，诊断记入不阻断接收的output.source参考信息。

版本6的角色生成将所有重复名称统一改为从setting继承：data不生成name/title/attackName，也不生成技能与奥义name。新Schema直接省略重复字段，旧返回仍兼容，名称差异不拒收。技能按数组顺序绑定，世界书格式段落与内置参考示例同步迁移，注入位置和自定义补充保留。

剧本v3以story保存五段自由小说文本：四场普通战斗各一段，Boss战后收尾一段；data保留原有元数据。文风、视角、节奏、篇幅与描写方式由导入预设主导，只提醒逐渐推进并留下伏笔。旧v1/v2响应和存档兼容。版本8替换项目自带的四个剧本规则，旧规则停用留存，注入位置、角色、深度、顺序及发送对象保留；自定义文风和导入预设不改。

## Kemini／Reborn正文适配

Kemini格式示例中的`{{思考内容}}`、`{{正文内容}}`与`{{可能要求的附加内容}}`保留为普通文字，包括它们位于变量值中的情况；真实宏继续展开，其余未知宏仍明确报错。

Reborn已启用的`game_content`单一正文工具绑定，会在上游请求中真正声明工具并指定调用它，提示词中的强制工具输出要求保持原样。API须支持`tools`及`tool_choice`；响应必须包含唯一一次已声明工具调用，完整正文置于其JSON参数的`content`中。支持非流式及流式工具参数，处理分块、转义、中文和Unicode代理对；不拼接外部普通正文，不执行工具动作、不追加第二次模型调用，也不会在失败时静默降级为普通输出。

解出的正文继续走游戏既有的`wanxiang_json`／`wanxiang_chat`／`wanxiang_actions`标签及数据校验。工具定义与选择会显示在请求预览中并计入TK，预设显式启用的ForcedPostProcessing会显示为本次实际后处理方式；工具模式不同时发送冲突的response_format。原始导入文件、预设文字、开关及扩展数据不修改。

Kemini的特殊传输在最终消息处理后插入正文传输工具及原有控制要求，使用auto工具选择。工具名称按最终请求内容生成，保证同一请求的预览与实际发送一致；支持流式和非流式，工具与普通正文并存时按原有较长正文规则选取一个结果。预设扩展窗口提供独立的“Kemini 特殊传输”开关，使用与该预设脚本相同的antiTruncationEnabled状态，按预设保存；关闭后请求不再带入传输工具。脚本与全局变量分开存于本机扩展存储，不进入AI消息或预设导出。

Reborn 2.4的已审阅消息数组后处理和输出预处理已接入，按导入脚本的指纹选择固定实现，不在服务端求值任意JavaScript。合并关闭时仍执行消息数组后处理；合并开启时先检查条件标记，命中才按前后缀、分隔标记进行合并，停止字符串也随相应设置发送。流式输出处理保留finishReason头部过滤、Unicode还原、代理对和标签分块状态。角色／剧本先解析并校验数据JSON，再对纯正文处理，避免破坏JSON转义与数值。预览列出本次处理状态；不匹配的脚本版本明确报错，不会静默换成普通输出。这里只支持已导入版本对应的配置，未提供任意插件或所有SPreset配置的通用执行器。

## Advice消息转移（仅酒馆聊天）

导入Izumi并启用其附带的泉此方助手脚本后，直接使用原悬浮窗的“Advice破甲开关”和齿轮设置；游戏不额外创建Advice面板或开关，也不用修改预设、添加自定义声明。原脚本写入的开关、前置／末尾、删除原有模型Advice及user续写指令会用于聊天请求。沿用Izumi私有存储键，默认关闭、末尾插入、删除旧Advice；前置时插入上一条AI最后的konatan_planning结束标签之后，并强制移除旧Advice。原预设文字和脚本保持不变。

只对本次保留的真实聊天楼层逐对生成发送投影：把玩家文字放入上一条AI的advice标签，本轮user改为续写指令，系统场景分隔层原样保留；不转移到预设示例或世界书消息。原始楼层、摘要和界面发言不改写，重试／编辑／删除后从现有记录重新组装，不重复堆叠。没有可配对AI楼层则保留正常user输入。世界书与角色提及扫描使用转换前的内容，发送正则先处理旧消息，再插入Advice，避免清理正则误删刚转移的输入；最终消息再参与原有后处理与TK统计。预览显示实际转换结果与状态，流式／非流式共用。仅使用input宏而关闭历史占位层的预设明确提示未应用，不丢弃输入。战斗闲聊、角色／剧本生成与总结不启用Advice。

转换实现可供其他适配器共用。已有的`extensions.wanxiang.advice`声明仍可读取`enabled`、`position`（head／tail）、`stripModelAdvice`、`replacementText`，但不创建额外设置界面；泉此方直接使用其原有设置，无需该声明。声明只配置固定转换，不执行任意请求钩子。未声明且不含启用的已识别助手脚本的预设不会自动启用。
