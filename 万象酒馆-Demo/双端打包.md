# Android 与 Windows 打包

两端从同一份 `npm run build` 产物打完整离线包。构建命令在复制前按索引核对全部初始与延迟资源的大小和 SHA-256；Android APK 与 Windows ZIP 均包含完整运行资源，不依赖热更镜像。

| 平台        | 方案                                                                           | 运行依赖                                                                                         |
| ----------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| Android     | Java Activity + 系统 WebView。AndroidX WebKit 提供限定来源的二进制文件写入通道 | Android 8.0 及以上，支持 `WEB_MESSAGE_LISTENER` 和 `WEB_MESSAGE_ARRAY_BUFFER` 的新版系统 WebView |
| Windows x64 | Go 标准库文件服务 + 本机默认浏览器，由 `WanxiangTavern.exe` 启动               | 支持现有 Web 版的现代浏览器                                                                      |

Capacitor 和 Cordova 适合继续接入多种设备插件。本阶段 Android 需要的原生能力只有 WebView 和应用私有文件存储。Tauri 可提供独立的 Windows 窗口，构建还需要 Rust/MSVC，运行依赖 WebView2。选用回环文件服务后，Windows 安装目录只需可执行文件和 `www/`，并沿用浏览器的存档、Worker 和网络行为。AndroidX 版本固定在 Gradle 工程，Windows 使用 Go 标准库。两端均无新增 npm 依赖。

## 构建完整离线包

在 `万象酒馆-Demo` 执行，需 Node.js 22.13 或更新版本。

```powershell
npm ci
npm run build
```

Android 构建需 JDK 17、Gradle 8.13、Android SDK Platform 36 及 Build Tools 35.0.0。让 `gradle` 在 `PATH` 中可用，并设置 `ANDROID_HOME` 或用 Android Studio 生成 `native/android/local.properties`。

```powershell
npm run build:android
```

APK 位于 `native/android/build/outputs/apk/debug/WanxiangTavern-debug.apk`，使用 Gradle 调试签名。发布包名为 `wanxiang-tavern-2.3-android.apk`；通过 `WANXIANG_ANDROID_VERSION_CODE` 为新包设置递增的整数，版本名取 `package.json` 的 `version`。

Windows 构建需 Go 1.25 或更新版本。

```powershell
npm run build:pc
```

交付 `.runtime/native/pc-win-x64/` 整个目录或将其打为 `wanxiang-tavern-2.3-windows-x64.zip`。双击 `WanxiangTavern.exe` 会打开默认浏览器并保持本地文件服务运行，关闭控制台即可停止。固定地址 `http://127.0.0.1:17371/` 用于延续浏览器存档。若端口被占用，先关闭占用该端口的进程再启动。

## 旧版热更产物

先填写要使用的镜像地址。地址以 `/` 结尾，指向同一版本的固定目录或 Release 标签。以下以 PowerShell 为例。

```powershell
$env:WANXIANG_UPDATE_GITHUB_RAW = 'https://raw.githubusercontent.com/OWNER/REPO/TAG/'
$env:WANXIANG_UPDATE_GITHUB_RELEASE = 'https://github.com/OWNER/REPO/releases/download/TAG/'
$env:WANXIANG_UPDATE_GITEE = 'https://gitee.com/OWNER/REPO/raw/TAG/'
npm run build
npm run build:updates
```

- `.runtime/native/updates/raw/` 用于 GitHub Raw 或 Gitee。上传整棵目录，保留 `assets/` 的相对路径。
- `.runtime/native/updates/github-release/` 用于 GitHub Release。将目录中的文件作为附件上传。一个 `asset-<sha256>` 可供同哈希的多个路径复用。

上述更新镜像流程仅保留给旧客户端；2.3 APK 和 Windows ZIP 使用随包的全部资源，不需要配置镜像或热更。

## 离线读取与版本

- Android 的下载目录为应用私有 `files/updates/v1/`，Windows 为 `%LOCALAPPDATA%/WanxiangTavern/updates/v1/`。
- 现有队列通过 `read`、`write`、`remove` 读写 `partial/` 与 `verified/`。壳只接受内置索引登记的分包路径和哈希，磁盘上以哈希命名。写入完整文件后以同目录重命名提交，半包目录只供续传读取。
- 启动后，模型、图片、音频等继续用原来的 URL。壳用本次随包发布的索引选择路径与哈希，优先读取校验通过的文件，再尝试包内同路径。仅存在于分包中的文件需下载后才能离线读取。
- 2.3 两端首次安装即可离线读取完整游戏资源。运行时更新清单仍保留旧版兼容，但发布包内已包含所有分包资源。
- 版本由 APK 或 Windows 包中固定的清单指定。升级壳后，相同哈希的已验证文件可继续使用，改动文件从本版本镜像下载。跨版本的 `checkForUpdate` 目前提供清单差异，客户端代码和首包清单随新安装包交付。

`npm run check:native` 只校验静态产物中的版本、分组和文件哈希，并打印首包和分包体积。
