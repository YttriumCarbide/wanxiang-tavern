# 五节点副本

本次仅在本地研发，不上传 GitHub、不发布正式网页。按提供的施工提示词实施；首次教程同样改为三战两次 RP，保留原有教学。

## 数据与流程

新剧本使用 schemaVersion 5，保留 story 五段及既有标题、标签、NPC、物品、伏笔和无限模式敌人配置。索引 0、2、4 为普通战、精英战、Boss；索引 1、3 分别为选项事件和自由 RP 任务。旧 v1～v4 剧本仍可读取，旧回忆仍按原结构运行。

data.adventure.event 定义事件标题、介绍和 2～4 个选项；选项 ID 由代码生成。正式选择确认后不可用补充文字更改。奖励复用库存和领取账本，事件使用被替换普通战的 20 金币价值预算，只允许金币与已有道具。第四节点完成后保留原另一场普通战的 20 金币；不调整 AP、行动次数、技能、速度、结合或敌人成长规则。

data.adventure.quest 定义场景、线索、共同到达状态与 2～6 个目标，至少一个主要目标。目标 ID 由代码生成，任务结果只允许更新已存在的目标，不清空遗漏目标或回退已完成目标。主要目标不能永久失败。完成主要目标先询问是否进入 Boss，拒绝后继续 RP；可选目标不阻止出发。

快速闲聊复用原客户端、预设、世界书和 Gal：第二节点只返回 wanxiang_chat 正文；第四节点额外返回 wanxiang_adventure JSON，含 episodeId、revision、tasks 和 patches。机器数据不进入 Gal。两节点提供全剧本，并明确区分已发生、当前和未来预定，未来只供衔接且禁止剧透。

## 剧情补丁与记录

Boss 台词由代码分配稳定 ID；替换保留 ID，插入分配新 ID，不移动旧编号。状态保存原始台词、当前台词、修订版本和补丁历史；后续调用读取当前版本。合法替换、相邻区间插入逐项应用，非法操作隔离。主要目标完成前不应用补丁；进入 Boss 时锁定，迟到响应不得改写正在播放的剧情。

原始生成剧本保存在 original。实际游玩记录只写已展开的 Gal 文本、选定选项、玩家行动、已确认目标与战斗经过。Gal 回退、重读和奖励重试不会重复归档。同一事件奖励和同一响应都有独立去重标识。

新五节点副本可从完整节点快照恢复，包含确认选项、领奖状态、任务、聊天与补丁；普通旧副本保留此前回大厅的兼容逻辑。手动存档和自动检查点使用同一快照校验。回忆不调用 API，RP 节点只重读已记录内容。

## 总结与界面

酒馆聊天继续手动总结。新副本只有完成归档才计入自动队列；满三份返回酒馆时批量请求，逐 ID 保存三份独立摘要。超出上下文时沿用总结计划分批处理，整组三份全部校验后才启用；失败保留原文及待处理状态，提示可重试，不阻塞酒馆。

第二、第四节点使用全屏场景配合边缘暗色渐层、轻量文字和选项，不使用绿色事件弹窗。桌面右侧安排叙事交互，手机横屏缩小字号和间距，内容区可滚动。进入 RP 时释放战斗场景，避免后台持续绘制。

十张背景由内置 imagegen 生成，位于 assets/events；每张地图各有 event、quest 两张。根据后续要求，默认使用未经缩放或有损转换的原始 PNG，已逐字节核对原始生成文件。生成提示词和原图SHA-256记录在 assets/events/prompts.json，原图同时保留在 Codex 生成目录。WebP 仅作为.runtime/art/webp-preview中的备用副本，不进入游戏资源目录。

## 验证范围

统一清单 tools/testing/checklist.json 包含相关核心、质量、服务、静态包、Gal、手机和 adventure 浏览器组。核心检查协议、奖励去重、任务更新、补丁稳定编号、快照和独立总结；adventure 组通过真实 UI 执行首次教程三场战斗、两个 RP 节点、失败重试、拒绝进入 Boss、连续补丁、存档恢复与返回后的三份总结。使用隔离数据及模拟 API，不调用真实付费模型。最终结果以 .runtime/tests/report.json 为准。
