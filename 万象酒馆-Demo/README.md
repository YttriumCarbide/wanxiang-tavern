# 万象酒馆 · 1.3 交流系统 Web Demo

这是本地运行的AI卡牌探索游戏原型。角色与剧本使用自己的OpenAI兼容服务；在酒馆副本门口选择五种环境、再在羊皮纸路线图选择副本节点，每次进入仍完成四场普通战斗与一场Boss。通关后程序在当前环境开放后续副本，剧情承接该路线的历史与伏笔；具体故事地点可以复用同一套场景美术。怪物组合随机确定，基础属性固定，暂不加入等级成长。版本阶段与遗留问题见[版本更新日志.md](版本更新日志.md)。

## 启动

需要 Node.js。项目已带上本地 Three.js 和模型，不需要安装 npm 依赖。

双击项目目录或上一级目录的 `一键启动.cmd`，会启动后台服务并打开浏览器；已经运行时直接复用。双击 `一键关闭.cmd` 停止本项目服务，不关闭浏览器窗口，也不停止其他 Node.js 程序。启动脚本会优先使用已安装的 Node.js，也能查找本机 Codex 自带的运行时。批处理入口使用纯ASCII命令和系统PowerShell完整路径，实际启动逻辑在 `launch.ps1` 中。

```powershell
cd D:\万界酒馆\万象酒馆-Demo
node server.cjs
```

浏览器打开 `http://127.0.0.1:4180/`。也可以执行 `npm run dev`。AI接口功能需要本项目的Node服务。不要直接双击HTML，模块和GLB均通过HTTP加载。

## 操作

1. 首次启动，或在存档窗口点“开启新冒险”，填写主角设定。先配置角色与剧本API、导入并选择提示词预设，再生成、检查主角档案并确认开局。生成失败可查看原始回复，尚未确认时不覆盖当前存档。
2. 新存档由主角与伊蒂丝进入遗迹，完成五场教学后返回召唤长景月汐；到桌边完成一次交流，再出发前往遗迹第二节点。准备界面可安排主角与最多五名同伴，不足六人时空位保持空白；主角始终出战。
3. 开战先获得1 AP，没有敌方行动。引导会教先手编排、正式回合的3 AP、敌方意图预演以及路途手记；旧存档沿用已有阵容和探索进度。
4. 战盘铺满窗口，镜头固定。回合提示在左上方，AP余量显示在左下圆环，透明背景的主时间轴在下方，备用卡在右下。结算／清空按钮位于右侧角色详情与备用卡之间。第一回合开始前，先手格在正常回合预览的左边，未来我方格暂时禁用；敌方格仍可查看意图。
5. 可先点击空时间格，再选角色、技能和目标；也可直接选前场角色、技能和目标，自动排到最早的可用格。无需指向的技能直接加入编排。可选对象显示移动虚线框，点空白或按Esc取消选择。
6. 可把前场卡拖进时间格，随后选技能，或点亮起的备用卡／“交换角色”；把备用卡拖进时间格，再选前场位置换入。已安排的行动可拖动调整顺序；拖到另一项行动上时，先同时校验两项行动，合法则直接交换位置。点×删除。2 AP技能占相邻两格。
7. 备用卡拖到前场、前场卡拖到备用卡，直接安排交换；前场拖到队友时可选交换或队友技能，拖到敌人时显示交叉双剑并可选攻击／技能。优先使用所选我方格，未选时使用最早可用格。交换均消耗1 AP。拖起的是完整三维体素卡，露出固定石座；取消会回位。场上资源条显示在石座下方，条内保留数字；敌人只有血条。后场卡平时只显示立绘，悬停或键盘聚焦时显示名字、血条、蓝条与状态，手机点选时显示。已有Buff常亮，预计新增Buff闪烁，悬停可看效果和结算后的资源。点击敌方时间格或敌人，可看本轮预计伤害、Buff和攻击位置的闪烁箭头；结算或取消时立即清理。
8. 检查实时预演；有冲突时先调整，再“确认结算”。结算只提示一次“回合开始”，随后连续播放整条时间轴，中途不再切换我方／敌方提示。演出可切到 ×2。普攻按剑、法杖、弓分型，每种敌人有独立攻击；包含起手、飞行／挥击和命中反馈。
9. 每场胜利进入营火结算。生命恢复，蓝量保持剩余值；点击“继续深入”进入下一场。第四场后是最终 Boss，第五场胜利后显示整个副本的战果。五场全部完成后，返回酒馆可选择当前环境新开放的后续副本；其他环境独立保存进度。中途返回或失败不解锁后续。

## 已实现规则

- 玩家正常每回合 3 AP；时间轴长度为 3 加本回合开始时存活的敌人数。
- 敌人只有速度属性，玩家没有速度。速度 1 排最后，速度 2 排倒数第二，超出长度则排最前；同速使用固定种子排序，编排期间不会重新随机。
- 迟缓技能会实时重排敌方位置。其他已编排技能保留原时间格，发生冲突时标红并禁止结算，不会偷偷自动移动。
- 普通攻击、技能均受角色技能出手次数限制；2 AP 技能仍算一次出手。换位／换人是队伍阵型指令，消耗 AP，不占角色技能出手上限。
- 每个角色有两个自定义技能槽，可为主动或被动，另有普通攻击。被动涵盖战斗外、全战斗、前场、后场四类生效位置。
- 力量、守势、虚弱、易伤、再生、中毒、迟缓、流血、铁皮全部生效；“神速”按后续修订删除。
- 流血在单位行动结束后触发。消耗 AP 的交换发起者也会触发流血。正常回合末先进行治疗／再生，再进行中毒；先手准备不触发回合末状态。
- 生命降到 0 立即濒死，不再恢复生命；此后已编排的技能显示红 × 并取消，不因此额外判为非法。时间轴箭头显示濒死发生在第几格之后，回合末中毒则标在末端。
- 敌人攻击左／中／右位置，不追踪角色；按实际执行时的阵型命中该位置的角色。
- 技能消耗蓝量，普通攻击不回蓝，回合间不回蓝。跨战斗也不恢复蓝量；返回酒馆重新出发才重置蓝量。
- 当前敌人全灭结束本场；所有实际出战角色全部濒死失败。护盾在下个正常回合开始清零，先手护盾保留到第一回合；状态层数在本场内持续，不自动衰减。
- 战间营火：存活角色回复35%最大生命，濒死角色恢复到35%最大生命；不恢复蓝量。阵型与蓝量保留，状态、护盾与出手次数重置。营火规则和数值为本次自行补充。

## 项目结构

- `src/app.js`：启动入口；`src/app/`：状态、输入、规划、视图、回放和副本控制器。
- `src/engine.js`、`data.js`、`expedition.js`、`validation.js`：纯规则、内容与契约。
- `src/scene.js`、`effects.js`、`motion.js`、`shared/`：三维、动画和资源生命周期。
- `src/tavern/`、`corridor.html`、`guest-room.html`、`master-bedroom.html`与`styles/tavern.css`、`styles/guest-room.css`、`styles/corridor.css`：主酒馆、二层走廊、两间客房和主卧视图。
- `styles/app.css`：样式入口，其余组件样式按职责维护，包含各自响应式规则。
- `tools/test.mjs`：唯一测试入口，范围与失败重跑逻辑位于`tools/testing/`。
- `tests/`：核心规则、契约和集中浏览器用例；布局基准在`tests/fixtures/`。
- `架构.md`、`开发规范.md`、`代码审查.md`：当前开发基线的结构、约定和验收说明。
- `assets/`、`vendor/`：模型、可替换立绘、Three.js及许可证。
- 上级`建模工具/`：独立Python开发环境和有效建模／几何脚本。

## 二层走廊与房间

主酒馆现有正门位于初始视野背后；靠近正门点击按钮会进入独立的`corridor.html`。原先额外加在酒馆前墙的客房木门已经移除。走廊左右分别是石砌墙裙、木梁、壁灯和长地毯；左墙并排三扇完全相同的木门，只有门上的黄铜编号牌不同；右墙另有一扇带回酒馆木牌的实体归门，两个方向的房门都能直接点击进入。尽头的虚空售货机使用独立5毫米体素柜体，四列三层的药水瓶按统一中心线、瓶底高度和标签朝向排列，完整保留玻璃柜框、投币器、九键面板、出货口和冷光货架。

三扇房门分别通往客房东厢`guest-room.html?room=a`、客房西厢`guest-room.html?room=b`和主卧`master-bedroom.html`。两间客房布局与家具基本一致，西厢把酒红织物调整成冷蓝织物。主卧是独立的11.2×9.2米房间，面积103.04平方米，约为客房51.2平方米的两倍：中央是2.6×2.9米双人床和四柱床幔，两侧各有床头柜与台灯，还配置石砌壁炉、窗榻、梳妆台、两个翼背椅和茶桌、大衣柜、书桌、书架、黄铜吊灯与大型徽记地毯。三间房都使用`src/tavern/room.js`，但主卧有独立的视觉点与灯光；床铺视角落在床面并望向房内，书桌椅直接复用酒馆大厅的椅子几何。走廊、客房和主卧底部只保留与大厅相同的“交流”入口；进入房间后回望房门会直接出现“离开房间”，不需要再先走到门口调整视角。走廊右墙实体归门可回到酒馆，左上角保留快捷返回。模型由单一占用体积生成，重叠盒体会合并并剔除内部面，地板和家具不会互相闪烁。模型源为`建模工具/build_tavern_guest_room.py`、`build_tavern_master.py`、`build_tavern_corridor.py`与共享的`tavern_chair.py`，运行资产为`assets/guest-room-a.glb`、`assets/guest-room-b.glb`、`assets/master-bedroom.glb`和`assets/corridor.glb`。

## 开发与测试

在本目录执行 `npm ci` 恢复锁定依赖。`npm run format`排版，`npm run lint`检查，`npm run check`运行质量和核心规则。编辑器设置支持保存格式化、诊断和Edge调试。完整目录说明见`架构.md`。

测试仍只通过 `tools/test.mjs` 一次提交本轮所需范围，例如 `npm test -- --scope quality,ui` 或 `npm test -- --changed src/app/selection.js,styles/cards.css`。失败用 `npm test -- --failed`，没有相关新改动的通过组不重复跑。UI与布局共用浏览器，长副本仅在相关改动或完整验收时执行。

旧版和冗余文件已进入回收站，当前代码不再依赖旧样式或旧查看器。清理记录在 `清理记录.md`。不自动生成ZIP。

## 音乐与音效

酒馆播放《炉边多利安》；霜晶矿窟小怪播放用户提供的《雪原》，其他地图小怪播放《遭遇战》。界隙遗迹Boss使用原小怪音乐《界门之战》，其他Boss使用《首领决战》。音乐均使用本地文件，场景切换时淡入淡出，相同音乐的战斗之间不重头播放。

首次点击／触摸页面或按键后启用声音，酒馆内点击同样有效。右上角喇叭按钮可分别调整、关闭音乐和音效，设置会保存在此浏览器；切到后台自动暂停，返回后恢复。

包含按钮、角色／时间格选中、技能选择、编排落位／交换、撤销、非法操作、拖起、界门、回合开始、治疗、护盾、胜负音效。剑、法杖、弓和十二种敌人攻击都有独立起手与命中声音，命中按动画进度和演出速度同步，预演时不播放攻击声。纹章结合另有独立的上升共鸣音；结合角色持续显示地面双环、上层符环、柔和光柱、粒子与卡牌边缘轻光，最强屏幕四边辉光和卡牌选中高亮只在选中该角色时出现。武器、敌人、界面与副本音效使用49份原创分层WAV采样，首次启用声音后在后台预载；载入期间仍由原有Web Audio合成声兜底。

早期合成曲谱与合成器保留在`tools/audio/`；生成音效的源脚本为`tools/audio/build_sfx.py`，输出在`assets/audio/sfx/`。音频拥有独立混音器、音量总线、淡入淡出和资源销毁入口，不参与战斗计算。

## 角色与剧本 API

酒馆顶部“设置”配置角色与剧本的Base URL、模型和密钥。靠近青色召唤门点击“召唤角色”，按双层JSON生成角色，设定集正文严格1000～1500参考tokens，数据编译后丢弃原始结构。靠近紫色副本门点击“进入剧本”，加载时生成本章，战场左侧手记随进度展示总开场、各站开场、动作对白和战间事件。完整说明见[API接入.md](API接入.md)。

提示词可在“设置 → 提示词预设”分层编辑，支持酒馆Chat Completion预设导入／导出与请求预览。API连接预设由角色和剧本共用，默认输出上限32768 tokens。文件与操作位置见[提示词修改入口.md](提示词修改入口.md)。

## 异境美术

在原有界隙遗迹、月痕古林、霜晶矿窟、余烬铸坊、潮汐星殿之后，新增朱阙宫庭、云海仙门、石堡校场、星辉秘庭、霓虹街口、量子舱室、荒原残站、黄沙神殿八张主题战场，共十三张地图。主题围绕各自的地标、地面、墙体和周边陈设展开：宫门与石狮、云海浮岛与玉门、城垛与操练木人、法阵与浮书、霓虹街口与停靠车辆、反应堆与服务器列阵、废站与锈车、神殿方碑与沙丘。矿车、锻锤、星环、水纹、小虫、微粒和无人机随场景运动；中毒、流血、再生在实际触发时播放局部动画。

每场战斗进入时会独立随机抽取天气：晴、细雨、落雪、雷雨或薄雾。天气由`scene-weather.js`在场景之外单独拥有自己的组，不参与地图模型、战斗规则或存档；雨滴、雪花、雾片、闪电帘和雷光只做观赏。副本路线窗口可打开“异境图册”，查看全部场景和四份新怪物模型。资源与细节见[美术扩展说明](美术扩展说明.md)。

当前测试模式：副本使用相同五段本地占位剧本，不调用剧本API，角色API正常。开关见 src/content/generation-mode.js。新存档从自定义主角与潘多拉开始，详见[主角开局与新手引导.md](主角开局与新手引导.md)。
