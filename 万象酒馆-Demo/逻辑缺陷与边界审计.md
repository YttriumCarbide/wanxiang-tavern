### A01 · P1 · 恢复异常计划可让时间格循环永久不前进

- 位置：src/validation.js:213；src/engine.js:178–194。
- 入口：storage/checkpoint.js:49–50 → adventure/snapshot.js:34–95 → app/journey.js:367–369 → preview。
- 输入：合法 2 AP 技能的 start 改为 `2 ** 53`。整数校验放行；引擎虽然标记越界，仍先执行逐格循环。此时 `start + 2 > start`，但 `start + 1 === start`，循环永不结束。
- 证据：logic-audit-plan 的不安全整数校验断言报红。为避免挂起验收，测试只调用 validateAction；死循环由逐行控制流和浮点舍入证明，没有实际启动无限循环。
- 建议：进入循环前立即排除越界/非法行动，并要求安全整数及有界 AP。

### A02 · P1 · 结合 followUp 覆盖 AP 与行动身份

- 位置：src/validation.js:218–222；src/engine.js:178–198、1166–1168。
- 输入：外层 engage.ap 为 0，followUp 带合法技能和 ap:1。内部校验采用嵌套 AP，占位却采用外层 AP，形成零占格施法；NaN/Infinity 的外层 AP 也未在该校验边界拒绝。嵌套 id 还能让 hero 事件偏离外层行动 ID。
- 证据：logic-audit-plan 的 3 个外层 AP 用例、零占格 preview、事件身份断言报红。非有限 AP 只调用校验器，没有进入危险循环。
- 建议：从明确白名单构造 followUp，校验外层实际 AP，保留外层 ID/时间格。额外 start 若被安全忽略，不作为独立缺陷。

### A03 · P1 · 反击前死亡仍攻击，随后直接恢复而复活

- 位置：src/engine.js:663–672；src/companion-mechanics.js:190–197。
- 场景：合法 beforeAttack 自伤规则在反击前杀死角色。反击未复查存活，返回后直接增加 HP/SP，绕过普通恢复对死亡目标的检查。
- 证据：logic-audit-engine-damage 的死亡回归得到 HP 9，正确预期为 0；测试允许正确实现直接取消后续事件。
- 建议：beforeAttack 后重新检查双方存活，反击恢复复用现有引擎恢复端口。

### A04 · P1 · 营业结算降低已超过 100 的好感

- 位置：src/service-live-settlement.js:41–46；规则对照 src/relationships.js:5–7、45–47。
- 场景：好感 150 的角色参加营业，结算使用 Math.min(100, affection + 2)，实际降至 100。当前好感系统允许每 100 点形成一级。
- 证据：logic-audit-service 预期 152，实际 100；相同角色承担多个岗位的去重与结算幂等对照另有覆盖。
- 建议：沿用统一好感累计规则，不把一级阈值作为总上限。

### A05 · P2 · 反击恢复绕过沉疫封锁

- 位置：src/companion-mechanics.js:190–192；对照 src/engine.js:272–297。
- 场景：封锁中的角色反击后仍直接恢复 HP/SP。普通 heal/restoreMana 均检查同一封锁，反击没有豁免契约。
- 证据：logic-audit-engine-damage 预期保持 HP 19，实际变为 28。
- 建议：复用引擎恢复端口，同时保持原有恢复事件与反击生命周期。

### A06 · P2 · 击杀条件无法匹配已经归零的目标

- 位置：src/triggers.js:220–225；src/engine.js:545。
- 场景：kill 事件发生后，合法 subject:target、hpBelow:0 条件被统一的死亡排除提前拦截，存活规则拥有者不能获得奖励。
- 证据：logic-audit-engine-damage 预期获得护盾 7，实际为 0；规则本身通过 normalizeRules。
- 建议：仅在击杀上下文允许检查被击杀目标，不全局放开死亡目标/拥有者。

### A07 · P2 · Schema 的 null 类型分支接受任意值

- 位置：src/ai/schema-check.js:30–50；真实协议 src/ai/character-schema.js:42、87。
- 场景：anyOf 中的 type:null 未实现类型检查，使非法字符串、数字、布尔、对象和数组命中该分支。
- 证据：logic-audit-ai 的 damageType 测试在直接校验、问题汇总、角色解析及共享生成入口共 20 条断言报红。
- 建议：实现严格 null 检查，保持直接校验与汇总一致。

### A08 · P2 · 汇总校验把原型链名称当成已声明字段

- 位置：src/ai/schema-check.js:68；对照同文件:34 的 own-property 检查。
- 输入：JSON 对象带 constructor、toString 或 `__proto__`，Schema 未声明这些字段。
- 证据：直接校验拒绝，但 outputSchemaIssues 返回空；logic-audit-ai 对三个键名的汇总断言报红。
- 建议：属性白名单使用 own-property 检查，保持错误路径一致。

### A09 · P2 · 生成重校验收到 JSON null 时出现原生 TypeError

- 位置：src/ai/pipeline/generation-result.js:115–117。
- 入口：用户编辑后的本地重校验文本也可进入该函数。
- 证据：logic-audit-ai 中直接角色解析能受控拒绝，但 readGenerationResult 对 null 在读取 schemaVersion 时抛 TypeError，未形成预期 schema 阶段诊断。
- 建议：先校验根对象类型，再读取版本字段。

### A10 · P2 · 多行代码围栏内的协议标签被当成真正边界

- 位置：src/ai/output-tags.js:109–115。
- 输入：wanxiang_output 正文的反引号或波浪线多行围栏内出现同名闭合标签。
- 证据：logic-audit-output 的扫描、完整聊天与流式正文三项报红；JSON 字符串转义、分片边界及独立处理器对照通过。

### A11 · P2 · 旧探索数据缺少 sequence 时传播 NaN 等级

### A12 · P2 · 新生成敌人的伤害可指向友方

### A13 · P2 · 继承属性可作为生成敌人的状态名

### A14 · P2 · 离客订单未取消，旧餐盘可完成复用桌位的新订单
